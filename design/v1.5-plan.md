# v1.5 — the crowd walks in, the home learns shapes, and every play teaches the feed

> **status: implemented** (phases 0–5, 2026-08-24). deviations from the
> plan below, all deliberate:
> - comment avatars render for top-level comments only; replies are
>   text-indented (keeps the fetch to ~40 tiny images per song).
> - charts country comes from the locale env (LANG → "US"), no picker yet.
> - typeahead ships without per-row suggestion *removal* (QCompleter has
>   no per-row buttons; a custom popup wasn't worth it this round).
> - top-songs chart block appears only on premium sessions (YT gates the
>   explore top-songs payload); charts-artists covers everyone else.
> - uploads tab (stretch goal) deferred with podcasts to a later release.
> - the wizard's play-reporting step always shows (with a dim "takes
>   effect only if you enable yt later" note when yt is off) — a stable
>   dot count beat a conditional step.

the next major update. one sentence: make youtube music silently the best
source in tide — full-depth integration, community data everywhere, a home
tab that stops being shelf-shelf-shelf — without ever labeling it "the good
source" in the ui. other sources keep their seats; capability gating does
the talking.

"silently" is a design rule, not a footnote: no YT branding creep, no
"premium source" badge, no feature ads. the depth just *is there* when the
active source is youtube music, and every surface degrades cleanly when it
isn't.

## why this is cheap for how big it looks

two discoveries from the audit:

**1. ytmusicapi 1.12 is ~70% unused.** tide calls eleven methods of it.
already installed, already authenticated through the cookie import, already
wrapped by the `_AuthSentinel` 401 watcher, sitting there:

| endpoint | what it unlocks |
|---|---|
| `get_song` | view count, upload date, the playbackTracking urls |
| `get_song_credits` | performed by / written by / produced by |
| `get_song_related` | "you might also like", "other performances", about-the-artist |
| `get_charts(country)` | ranked top songs/videos/artists with trend arrows |
| `get_explore` | new releases, moods entry point |
| `get_mood_categories` / `get_mood_playlists` | the moods & genres tree |
| `get_history` / `add_history_item` / `remove_history_items` | YT-side play history, and *writing* to it |
| `get_library_songs/albums/artists/subscriptions` | the actual library, not just playlists |
| `create/edit/delete_playlist`, `add/remove_playlist_items` | playlist management |
| `subscribe_artist`, `rate_playlist`, `edit_song_library_status` | follow artists, save albums/playlists to library |
| `get_search_suggestions` / `remove_search_suggestions` | typeahead |
| `get_tasteprofile` / `set_tasteprofile` | tune the recommendation engine directly |

**2. the resolver already downloads community data and throws it away.**
`resolve_stream_url` calls yt-dlp `extract_info` for every played track and
keeps exactly one field (`url` — [ytmusic.py:845](../src/tide/sources/ytmusic.py)).
the same info dict carries `view_count`, `like_count`, `comment_count`,
`upload_date`, `channel`. views and likes for the now-playing track cost
**zero additional network**.

## the four pillars

### pillar 1 — the feedback loop (the invisible one that makes everything else good)

tide currently *reads* youtube music and never writes back. plays in tide
don't count: "listen again" goes stale, quick picks drift, the algorithm
thinks you stopped listening. every other pillar gets better when this
lands, so it lands first.

- **plays report back.** on playback start (the hook is right after
  `history_module.append` in [window.py:1696](../src/tide/ui/window.py)),
  a worker calls `get_song(videoId)` → `add_history_item(response)`. one
  round trip per play, and the same `get_song` response feeds the insight
  strip (pillar 2), so the fetch is shared, not doubled.
  - **chosen at first startup**: the onboarding wizard gets a step that
    explains in plain words what play reporting is (each play sends the
    same "I listened to this" ping the yt music web player sends, to your
    own signed-in account, so recommendations learn from tide) and what
    it means for privacy (google sees your listening; off = google learns
    nothing from tide). no pre-checked box — the user decides. the same
    toggle lives in settings → integrations for changing your mind later;
    upgraders who never see the wizard default to **off**.
  - skip when signed out, skip non-yt tracks, skip session restores (same
    guard history uses).
- **dislike / "less of this".** `rate_song(id, "DISLIKE")` — context menu
  everywhere a track row exists, plus a button on the song page. the like
  button already exists; this is its shadow.
- **taste profile editor.** `get_tasteprofile` / `set_tasteprofile` — a
  grid of artists with checkmarks, in the yt music gear dialog on the
  sources tab. directly steers what `get_home` returns.
- **honest fallout:** home recommendations visibly improve after a week of
  reported plays. that's the update's sleeper feature and we never have to
  build a recommender.

### pillar 2 — the community layer (views, likes, comments, credits)

right now a track in tide is title/artist/album/duration. on youtube music
it's a place where 12,000 people said things. bring that in, in tide's own
brutalist voice — dim monospace counts, ascii markers, no material-design
cards.

- **counts on the now-playing strip.** a dim one-liner under the title:
  `2.1m plays · 43k likes · 2016`. harvested free from the resolver's
  info dict; cached 24h per video id; absent silently when unknown
  (local files, subsonic — nothing renders, no empty husk).
- **the song page.** the centerpiece. click the now-playing title/art (or
  context → "song info") and get a native watch-panel:

  ```
  ┌────────────────┐  nights                       [related] [comments] [credits]
  │                │  frank ocean · blonde · 2016  ─────────────────────────────
  │   album art    │  84.2m plays · 1.1m likes     ▸ you might also like …
  │                │  [♥] [+ playlist] [radio]     ▸ other performances …
  └────────────────┘  [↓ not for me]               ▸ about the artist
  ```

  - **related tab** — `get_song_related(browseId)`: "you might also
    like", "other performances" (covers! remixes! live cuts!), "about the
    artist". rendered with the existing card/shelf widgets.
  - **credits tab** — `get_song_credits`: performed / written / produced
    by. plain text list, the metadata-nerd surface no major app bothers
    with anymore.
  - **comments tab** — see below.
- **comments.** ytmusicapi has no comments api; yt-dlp does:
  `extract_info(url, {"getcomments": True, "extractor_args": {"youtube":
  {"max_comments": ["60,all,20"], "comment_sort": ["top"]}}})` returns
  author, avatar url, text, like count, reply count, pinned/hearted flags,
  relative time. design:

  ```
  ── comments · 12,041 ─────────────────  sort: [top] newest
   @plasticbeachfan · 2y · 3.4k ♥ · pinned
     this song rewired my brain chemistry
     └ 41 replies
   @user2 · 8mo · 812 ♥
     the beat switch at 3:31 is the single greatest …
  ```

  - lazy: fetched only when the tab opens, worker thread, session-cached.
    first load is honestly 1–3s — spinner with the loading-indicator style
    the user already picked.
  - **timestamps in comments are seek links.** regex `\b\d?\d:\d\d\b`,
    accent-colored, click to seek. cheap, delightful, no major app does it.
  - avatars ride the existing `art_cache`, circular mask like artist cards.
  - **read-only, deliberately.** posting/liking comments means driving
    innertube write endpoints with harvested cookies — fragile and not
    worth risking anyone's google account. maybe never; definitely not v1.5.
- **counts in lists where the payload already carries them.** video search
  results and some shelf payloads include a views string — show it in the
  subtitle instead of discarding it. no per-row fetches, ever.
- **artist page upgrades.** subscriber count already renders; add
  **[subscribe]** / [subscribed] via `subscribe_artist` /
  `unsubscribe_artists`, and per-song plays on top songs when the payload
  carries them.
- **album page upgrades.** **[+ library]** via `rate_playlist(LIKE)` on
  the album's audioPlaylistId; year · duration · track count line
  (`AlbumDetail` already has the fields).

### pillar 3 — the home rework (grids and patterns, not shelves)

today home = heading + horizontal card row, × N
([explore.py:141](../src/tide/ui/explore.py)). the rework is a **layout
engine**: home becomes a list of *blocks*, each block owns a *pattern*, and
the pattern is chosen per shelf by what's in it.

**the patterns** (new `ui/home/` package; `Card` grows size variants,
`ShelfRow`/`CardGrid` stay for reuse):

| pattern | shape | fed by |
|---|---|---|
| `hero` | full-width banner: greeting, resume card with big art, blurred-art backdrop | local session + history |
| `tap_grid` | YT's quick-picks shape: compact rows (art · title · artist · plays) in 4-row columns, paged ‹ 1/3 › | songs shelves |
| `mosaic` | one 2×2 featured tile + 1×1s around it, arrangement seeded by day so it reshuffles daily | mixed album/playlist shelves |
| `dense_grid` | small square tiles, 6–8 across, 2 rows | listen again |
| `circle_row` | circular artist tiles | artist shelves |
| `ranked_list` | big dim numerals, trend arrows ↑↓— | charts |
| `chip_row` | pill buttons | moods & genres |
| `shelf_row` | the current look | fallback, and non-YT sources |

**pattern assignment**: match shelf title against the stable YT names
("quick picks", "listen again", "mixed for you", …) → else heuristic on
item kinds (all-artists → circle_row, all-songs → tap_grid, mixed →
mosaic) → else shelf_row. every block isolated in try/except: a parser
break in one block renders the rest, never a blank home.

**the assembled page** (interleaving YT shelves with local blocks):

```
good evening, captience            3h 12m this week · mostly frank ocean
┌──────────────────────────────────────────────────────────────┐
│ ████████  keep listening                                     │
│ ██hero██  blonde — frank ocean                               │
│ ████████  ▶ resume · [radio] [shuffle likes]                 │
└──────────────────────────────────────────────────────────────┘

 [▪][▪][▪][▪][▪][▪][▪]
── mixed for you ─────────────────────────────────────────────
 ┌────────┐ ┌───┐ ┌───┐ ┌───┐
 │        │ │▪  │ │▪  │ │▪  │

 │        │ ┌───┐ ┌───┐ ┌───┐
```

- **greeting header**: time-of-day + account name (already fetched by
  `probe_auth`) + a one-line local stat from history.jsonl.
- **hero / keep listening**: resume the saved session, jump back into the
  last album/playlist, shuffle-likes shortcut. local data, works for every
  source.
- **charts block** → `get_charts(country)`; country picker in the block
  header, default from locale, cached 6h. clicks through to a full charts
  browse page (songs / videos / artists tabs).
- **moods chips** → `get_mood_categories` cached 24h; a chip opens a
  `get_mood_playlists` grid page.
- **new releases** → `get_explore`, cached 6h.
- **lazy below the fold**: build the top ~2 blocks immediately, the rest
  as the scroll viewport reaches them; `get_home(limit=…)` goes 6 → 12 for
  more shelves to feed the engine.
- **settings escape hatch**: appearance → "home layout: patterns /
  plain shelves" for anyone who liked the old austerity.
- non-YT sources: subsonic/local home shelves flow through the same
  engine and get hero + shelf_row + their own local blocks. nothing
  breaks, it just has fewer shapes.

### pillar 4 — library and playlist parity (the full experience part)

the library tab shows playlists and liked songs. the actual yt music
library is five times that.

- **library tabs**: playlists · songs (`get_library_songs`) · albums
  (`get_library_albums`) · artists (`get_library_artists`) · subscriptions
  (`get_library_subscriptions`), with the a-z / recent sort orders the api
  takes. capability-gated per source (subsonic can fill several of these
  later; local files already have albums/artists surfaces to wire in).
- **playlist management, everywhere**:
  - context menu on any yt track, any view: **"add to playlist ▸"** with
    the user's playlists + "new playlist…" (`add_playlist_items`,
    `create_playlist`).
  - playlist view: remove track, rename, edit description, toggle
    privacy, delete (`remove_playlist_items`, `edit_playlist`,
    `delete_playlist`) — destructive ones behind a confirm.
  - **"save queue as playlist"** in the queue view — the mixed-source
    queue saves its yt tracks and reports how many it kept. no other
    player treats the queue as a draft playlist; tide should.
- **add to library** from anywhere: songs via `edit_song_library_status`
  feedback tokens, albums/playlists via `rate_playlist`, artists via
  subscribe.
- **history goes double-sided**: the history view gets `[tide] [youtube]`
  tabs — the YT tab is `get_history` (plays from your phone, the web, all
  of it) with per-row remove (`remove_history_items`). with pillar 1
  reporting plays, the two sides converge — that's the point.
- **search grows a playlists filter** (`filter="playlists"` — community
  playlists, the crowd's own curation) next to songs/videos/albums/
  artists. this is discovery-by-other-humans, the oldest community
  feature there is.
- **typeahead**: `get_search_suggestions` on a 150ms debounce under the
  search bar, arrow-key navigable; history-sourced rows get an `[x]`
  (`remove_search_suggestions`).
- stretch, if the tabs go fast: uploads (`get_library_upload_*`) as a
  sixth library tab.

## data layer changes (the part under all four pillars)

- **`sources/base.py`**: new dataclasses — `SongInsights` (views, likes,
  comment count, upload date, channel), `Comment`, `CreditsBlock`,
  `ChartEntry`, `MoodCategory`, `LibraryAlbumEntry`… plus new capability
  keys: `"insights"`, `"comments"`, `"credits"`, `"related"`, `"charts"`,
  `"moods"`, `"library_full"`, `"playlist_edit"`, `"subscribe"`,
  `"history_sync"`, `"suggest"`. views check `supports()` exactly like
  today — that's the whole degradation story.
- **`sources/ytmusic.py`**: implement the above; every new call rides the
  existing `_AuthSentinel`, so 401 handling and the silent token refresh
  come for free. charts/moods/comments/insights work anonymously — they
  must survive a dead cookie jar.
- **resolver harvest**: `_extract_stream_url` returns url + insights;
  insights land in a new cache table keyed by video id (24h TTL) that the
  now-playing strip and song page read first.
- **`cache.py`**: grow a small generic JSON-payload TTL cache next to the
  stream-url one — charts 6h, moods 24h, explore 6h, home 15m, insights
  24h, credits/related 7d (they don't change).
- **request budget honesty**: cold home = 1 `get_home` + cached charts +
  cached moods + thumbnails. per play = 1 `get_song` (shared by insights +
  history ping). comments = 1 lazy call on tab open. that's *less* chatter
  than the yt music web player.

## risks, named

- **ytmusicapi parse fragility** — youtube reshapes payloads whenever it
  feels like it. mitigation: per-block isolation on home, per-tab
  isolation on the song page, everything optional-rendered; a break
  degrades to absence, never to a broken view. (the codebase already
  learned this lesson with `_SIGNED_OUT_MARKERS`.)
- **comments latency** — 1–3s first load. lazy + spinner + session cache;
  never fetched unless the tab is opened.
- **play reporting is a write** — it's the documented tracking ping the
  web player sends, but it must be a visible, honest setting. one toggle,
  integrations tab, plain words. also: some people use tide precisely to
  keep google at arm's length — the toggle is for them.
- **home perf** — 10+ blocks × 20 tiles of art. lazy build below the
  fold; `art_cache` is already async; card paint stays the cheap
  QPainter path it is now.
- **scope creep** — the phases below are each shippable; if 1.5 needs to
  ship early, cut from the bottom of the phase list, never from within a
  phase.

## explicitly not in v1.5

- **posting/liking comments** — account risk, innertube write fragility.
- **podcasts** (`get_podcast`/episodes) — real feature, own update (1.6?).
- **collaborative playlist join** — niche until playlist editing has soaked.
- **a tide account system / cross-user features** — the community layer
  is youtube's crowd, not a tide social network.

## build order

| phase | what ships | size |
|---|---|---|
| 0 | data layer: dataclasses, capability keys, JSON cache, resolver harvest | S |
| 1 | feedback loop: play reporting + setting, dislike, `get_song` insights, now-playing counts strip | M |
| 2 | song page: related / credits / comments tabs, timestamp seek links | L |
| 3 | home engine: block model, 8 patterns, greeting/hero, charts + moods + new releases blocks, lazy fold, plain-shelves setting | XL |
| 4 | library tabs, playlist management everywhere, save-queue-as-playlist, subscribe/add-to-library, history double-side, playlists search filter | L |
| 5 | polish: typeahead, taste profile editor, stats blurb in the greeting, wizard mention of play reporting, README/screenshots | M |

phases 1–2 make yt music the deepest source anyone's shipped in a native
player. phase 3 makes it *look* like it. phases 4–5 make it complete.
